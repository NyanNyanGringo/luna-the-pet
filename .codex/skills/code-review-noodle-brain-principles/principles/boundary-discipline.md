# Дисциплина границ

**Принцип:** Размещай валидацию, сужение типов и обработку ошибок на границах системы. Внутреннему коду доверяй безусловно. Бизнес-логика живёт в чистых функциях; внешняя оболочка тонкая и механическая.

## Зачем

Валидация, размазанная по всей кодовой базе, создаёт шум, дублирование и ложное чувство безопасности. Если сосредоточить её на границах, каждый фрагмент данных проверяется ровно один раз: в момент входа в систему, после чего свободно проходит дальше. Точно так же логика, переплетённая с кодом фреймворка, не тестируется без него и не переиспользуется в других контекстах.

## Шаблон

- **На границах** (аргументы CLI, конфиг TOML, внешние API, протокол NDJSON): валидируй, возвращай `error`, обрабатывай защитно.
- **Внутри системы**: типизированные данные, проброс через `return err`, без повторной валидации. Доверяй типам.

## Применение

### Валидация и обработка ошибок

- Все CLI-команды возвращают `(T, error)`: ошибки обрабатываются на границе команды, а не внутри бизнес-логики.
- В production-коде нет `panic()`: пробрасывай ошибку через `return err`.
- Конфиг валидируется во время парсинга, на границе TOML, а не внутри бизнес-логики.
- Сырые данные хранятся на границах системы (`json.RawMessage`): разбирай их лениво в месте использования.

### Организация кода

Бизнес-логика живёт в чистых функциях без зависимостей от фреймворка (`(Input) => (Output, error)`). Оболочка, то есть роутинг CLI, обработка событий TUI и управление tmux, остаётся тонкой и механической.

- **Функции парсинга**: чистые преобразования `([]byte) => (State, error)` без зависимостей от runner или TUI.
- **Построение промпта**: `buildBrief()` получает структурированное состояние и возвращает строку промпта.
- **Оценка и скоринг**: чистые преобразования `(BacklogState) => []ScoredItem` без побочных эффектов.

## Проверки

Перед тем как добавить новую проверку валидации, спроси: **«Эти данные прямо сейчас пересекают границу системы?»** Если нет, валидация лишняя: доверяй типам.

Перед тем как положить логику в hook, listener событий или точку интеграции с фреймворком, спроси: **«Можно ли вынести это в чистую функцию, которую оболочка просто вызовет?»** Если да, выноси.
