# Делегирование с учётом стоимости

**Принцип:** У каждой границы делегирования есть бюджет. Учитывай накладные расходы самого делегирования и жёстко ограничивай объём, чтобы работа не разрасталась под доступные ресурсы.

## Зачем

Ходы агента, минуты CI и деньги на API конечны. Без явных бюджетов работа расползается на всё доступное: CI зависает по таймауту, агенты тратят 5 ходов на повторное восстановление уже известного контекста, а координационные издержки съедают запас.

## Шаблон

- **Сначала закладывай бюджет.** Считай ходы по фазам: настройка (2-3), чтение контекста (1-2), реализация (2-5), проверка и исправления (2-4), git-операции (2-3). Если сумма > `budget - 7`, объём слишком большой.
- **Заранее передавай контекст, чтобы не платить за переоткрытие.** Каждый кусок анализа, который не передали, превращается в потерянный ход. Цена длинного промпта: одно чтение. Цена повторного восстановления контекста: 3-5 ходов.
- **Жёстко ограничивай объём.** Не больше 2-3 файлов на фазу CI. Не больше 1 функции или типа плюс тесты на фазу. Без лимитов работа расползается.
- **Учитывай стоимость координации.** `TeamCreate` стоит 8-10 ходов на координацию. Подагенты задач возвращают результат напрямую и экономят 5-7 ходов. Выбирай более дешёвый механизм, если реальная координация не нужна.
- **Выходи вовремя, а не в последний момент.** Фиксируй проходящую работу на `budget - 7`, а не на `budget - 5`. Git-операции стабильно стоят 2-3 хода.

## Связь с другими принципами

Этот принцип не о том, *что* строить ([[principles/foundational-thinking]]) и не о том, *как* это структурировать ([[principles/boundary-discipline]]). Он об экономике ситуации, когда кто-то другой делает работу за тебя: внимание рассматривается как ограниченная валюта.
