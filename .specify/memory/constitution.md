# Конституция проекта «Луна»

## Основные принципы

### I. Открытый исходный код без ограничений

Этот проект ДОЛЖЕН оставаться полностью открытым без лицензионных
ограничений, ограничений использования или распространения. Весь код,
документация и ресурсы ДОЛЖНЫ быть свободно доступны каждому.

- Платные функции, подписки или премиум-уровни запрещены.
- Телеметрия, аналитика или сбор данных за пределами того, что владелец
  явно настраивает на своём сервере, запрещены.
- Вклады сообщества приветствуются без требований CLA.

### II. Голос как приоритет, мультимодальный ввод

Основной режим взаимодействия — естественный язык через Telegram
(голосовые сообщения и текст). Система ДОЛЖНА обрабатывать голос, текст
и фото как полноценные каналы ввода.

- Голосовые сообщения ДОЛЖНЫ транскрибироваться и обрабатываться с той же
  точностью, что и текстовый ввод.
- Фотографии ДОЛЖНЫ анализироваться с автоматическим извлечением метаданных
  (например, состояние питомца, сканы документов, карточки вакцинации).
- Пользователь НЕ ДОЛЖЕН изучать специальный синтаксис команд; естественный
  язык — это интерфейс.

### III. Комплексная база знаний о питомцах

Основная ценность — накопление полной, структурированной и запрашиваемой
истории каждого питомца. Каждое взаимодействие ДОЛЖНО вносить вклад
в построение этой базы знаний.

- Система ДОЛЖНА хранить: данные профиля (имя, день рождения, порода,
  история веса, происхождение), записи о вакцинации с датами, медицинскую
  историю (болезни, операции, кастрация), графики приёма лекарств, историю
  диеты/корма, дневник кормления и произвольные заметки.
- Историческая перспектива ДОЛЖНА сохраняться: при изменении данных
  (например, смена марки корма) предыдущее значение и диапазон дат
  ДОЛЖНЫ быть сохранены, а не перезаписаны.
- База знаний ДОЛЖНА поддерживать нескольких питомцев на одно домохозяйство.

### IV. Проактивный уход и напоминания

Система НЕ ДОЛЖНА быть исключительно реактивной. Она ДОЛЖНА проактивно
напоминать, контролировать и подсказывать семье о задачах по уходу за
питомцем.

- Напоминания о лекарствах ДОЛЖНЫ планироваться на основе назначенной
  частоты (например, «каждые 3 месяца») и срабатывать вовремя.
- После срабатывания напоминания система ДОЛЖНА отправить контрольное
  сообщение для подтверждения выполнения действия (например, «Вы дали
  Луне лекарство?»).
- Даты ревакцинации ДОЛЖНЫ отслеживаться, а напоминания отправляться
  заблаговременно.
- Система МОЖЕТ предлагать ветеринарные осмотры на основе возраста
  и паттернов медицинской истории.

### V. Архитектура диалогового агента

Система работает как AI-агент на базе OpenAI API со структурированными
вызовами инструментов. Агент ДОЛЖЕН иметь доступ к полной базе знаний
о питомце как контексту при ответе на вопросы.

- Агент ДОЛЖЕН использовать вызовы функций/инструментов для чтения и
  записи структурированных данных (не только парсинг свободного текста).
- Когда семья задаёт вопросы о здоровье, агент ДОЛЖЕН учитывать полную
  историю питомца (вакцинации, лекарства, состояния, диету) перед ответом.
- Агент ДОЛЖЕН чётко различать фактические данные о питомце и
  сгенерированные AI советы, а также рекомендовать консультацию ветеринара
  при серьёзных проблемах со здоровьем.

### VI. Простота для семьи

Это семейный проект. Каждый член семьи ДОЛЖЕН иметь возможность
взаимодействовать с системой без технических знаний.

- Telegram — основной интерфейс; терминал или веб-вход НЕ ДОЛЖНЫ
  требоваться для ежедневного использования.
- Веб-панель служит вторичным интерфейсом для просмотра и управления
  и ДОЛЖНА быть интуитивно понятной.
- Сообщения об ошибках ДОЛЖНЫ быть понятны людям, без отображения
  стек-трейсов или технического жаргона семейным пользователям.
- Система ДОЛЖНА корректно обрабатывать неоднозначный или неполный ввод,
  задавая уточняющие вопросы при необходимости.

### VII. Самохостинг и уважение к конфиденциальности

Все данные о питомцах и семье ДОЛЖНЫ храниться на собственной
инфраструктуре семьи. Никакие сторонние сервисы не могут хранить данные
о питомцах за пределами транзитных API-вызовов.

- Система ДОЛЖНА разворачиваться на одном Ubuntu VDS через SSH без
  сложной оркестрации.
- Внешние API-вызовы (OpenAI, Telegram) ДОЛЖНЫ передавать только
  минимум данных, необходимых для обработки.
- Резервное копирование ДОЛЖНО поддерживаться для предотвращения
  потери данных.
- Развёртывание через Docker ДОЛЖНО быть стандартным вариантом для
  воспроизводимости и удобства обновлений.

## Технологический стек и ограничения развёртывания

Следующие технологические решения являются обязательными для этого проекта:

- **Язык**: Python 3.11+
- **Веб-фреймворк**: FastAPI (для веб-панели и webhook-эндпоинтов)
- **Telegram-бот**: aiogram 3.x (асинхронный фреймворк Telegram-ботов)
- **AI-бэкенд**: OpenAI API (модели GPT с вызовами функций)
- **База данных**: PostgreSQL (с SQLAlchemy или asyncpg как ORM/драйвер)
- **Обработка голоса**: OpenAI Whisper API для преобразования речи в текст
- **Целевая платформа**: Ubuntu VDS, доступный через SSH
- **Контейнеризация**: Docker + Docker Compose для развёртывания
- **Миграции**: Alembic для миграций схемы базы данных

Все зависимости ДОЛЖНЫ быть закреплены на конкретных версиях в файлах
требований. Система ДОЛЖНА работать на скромном VDS (2 CPU, 4 ГБ RAM)
без деградации производительности для нагрузки одной семьи.

## Управление данными и модель взаимодействия

Все взаимодействия следуют паттерну: **Ввод -> Обработка агентом
-> Структурированное хранение + Ответ**.

- **Каналы ввода**: голосовые сообщения Telegram, текст Telegram,
  фото Telegram, формы веб-панели.
- **Обработка**: OpenAI-агент извлекает структурированные данные из
  естественного языка, вызывает соответствующие инструменты для чтения/записи
  базы данных.
- **Хранение**: все данные о питомцах хранятся в PostgreSQL с правильными
  связями, временными метками и аудит-трейлами.
- **Вывод**: ответы на естественном языке через Telegram, структурированные
  представления через веб-панель.
- **Напоминания**: планировщик (например, APScheduler или Celery Beat)
  выполняет периодические проверки просроченных напоминаний и отправляет
  уведомления в Telegram.
- **Сборка контекста**: перед ответом на вопросы о здоровье агент ДОЛЖЕН
  получить релевантные разделы истории питомца для включения в контекст LLM.
