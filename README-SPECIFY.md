# Доступные команды

`/speckit.constitution`
Создаёт или обновляет «конституцию» проекта — необсуждаемые принципы качества.

`/speckit.specify`
Преобразует описание на естественном языке в структурированную спецификацию:
 user stories
 functional requirements (FR)
 success criteria

`/speckit.plan`
Исследует unknowns
- Выбирает стек
- Генерирует:
  - data-model
  - API-контракт
  - quickstart
  - план реализации

`/speckit.tasks`
Генерирует `tasks.md` — 67 задач по фазам и user stories с зависимостями.

`/speckit.clarify`
Задаёт до 5 уточняющих вопросов по `spec` и вписывает ответы обратно в файл.
Используется, если спецификация размыта или остались неопределённости после `specify`.

`/speckit.checklist`
Генерирует кастомный чеклист для фичи по произвольным критериям
(например: «проверь безопасность» или «проверь доступность»).

`/speckit.analyze`
Статический анализ согласованности артефактов:
 проверяет, что `spec`, `plan`, `tasks` не противоречат друг другу
 проверяет соответствие конституции

Работает в режиме только чтения — ничего не изменяет.

`/speckit.implement`
Выполняет задачи из `tasks.md` по порядку — непосредственно пишет код.

`/speckit.taskstoissues`
Конвертирует задачи из `tasks.md` в GitHub Issues с зависимостями и метками.



# Полный workflow

```text
constitution → specify → [clarify?] → plan → [analyze?] → tasks → [checklist?] → implement → taskstoissues
```


# Маленькие фичи в Speckit

> Главный принцип: workflow масштабируется под размер задачи.

## Уровни сложности

### Уровень 1 — Микро-изменение

Пример: цвет кнопки, текст, отступ.

→ Просто реализовать.
Команды Speckit не нужны.

### Уровень 2 — Маленькая фича

Пример: новый компонент, экран, форма.

```text
/speckit.specify
→
/speckit.implement
```

`plan` и `tasks` не нужны, если нет технических unknowns.

### Уровень 3 — Средняя фича

Пример: новый раздел с API или новая сущность БД.

```text
/speckit.specify
→
/speckit.plan
→
/speckit.implement
```

`tasks` можно пропустить, если задач меньше ~10.

### Уровень 4 — Большая фича

```text
constitution → specify → plan → tasks → implement → taskstoissues
```

### Пример: тёмная тема

```text
/speckit.specify
Добавить переключатель тёмной/светлой темы в шапку.
Настройка сохраняется между сессиями.

/speckit.implement
```

`plan` и `tasks` избыточны.

### Как определить уровень

| Вопрос | Если да |
| --- | --- |
| Нужны изменения в БД или API? | Уровень 3+ |
| Затрагивает больше 5 файлов? | Уровень 2+ |
| Есть технические unknowns? | Уровень 3+ |
| Меняется только UI? | Уровень 1–2 |
| Это правка существующего? | Уровень 1 |
