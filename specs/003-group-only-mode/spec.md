# Спецификация фичи: Групповой режим работы бота

**Ветка фичи**: `003-group-only-mode`
**Создано**: 2026-03-12
**Статус**: Черновик
**Входные данные**: Описание пользователя: «Бот должен работать только при добавлении в группу. Если запускать бота без добавления в группу, он просит создать группу и даёт инструкцию как это сделать краткую. Таким образом функционал расшаривания сессий не нужен, так как бот живёт внутри группы и привязывается к ней. Команда /invite в таком случае даёт ссылку на группу.»

## Пользовательские сценарии и тестирование *(обязательно)*

### Пользовательская история 1 — Бот отклоняет личные сообщения и направляет в группу (Приоритет: P1)

Пользователь пишет боту в личный чат (private chat). Бот не обрабатывает сообщение по существу, а отвечает кратким сообщением с инструкцией:
1. Создайте группу в Telegram
2. Добавьте бота в группу
3. Начните пользоваться

Инструкция должна быть лаконичной (3–5 шагов), понятной нетехническому пользователю и содержать только текст (без внешних ссылок, без скриншотов). Бот отвечает так на любое сообщение в личном чате: текст, голос, фото, команды.

**Почему такой приоритет**: Это точка входа для каждого нового пользователя. Без понятного перенаправления пользователь решит, что бот не работает, и уйдёт.

**Независимый тест**: Написать боту в личный чат любое сообщение. Получить инструкцию по созданию группы. Убедиться, что бот не обработал содержимое сообщения.

**Сценарии приёмки**:

1. **Дано**: пользователь не состоит ни в одной группе с ботом, **Когда** он отправляет текстовое сообщение в личный чат бота, **Тогда** бот отвечает инструкцией по созданию группы и добавлению бота.
2. **Дано**: пользователь не состоит ни в одной группе с ботом, **Когда** он отправляет голосовое сообщение в личный чат бота, **Тогда** бот отвечает той же инструкцией (без транскрибирования аудио).
3. **Дано**: пользователь не состоит ни в одной группе с ботом, **Когда** он отправляет команду `/start` в личный чат, **Тогда** бот отвечает приветствием и инструкцией по созданию группы.
4. **Дано**: пользователь состоит в одной группе с ботом, **Когда** он пишет боту в личный чат, **Тогда** бот отвечает сообщением «Я работаю только в группе» и даёт ссылку на эту группу.
5. **Дано**: пользователь состоит в нескольких группах с ботом, **Когда** он пишет боту в личный чат, **Тогда** бот отвечает сообщением «Я работаю только в группах» и выдаёт список групп, в которых пользователь состоит.

### Пользовательская история 2 — Бот привязывается к группе при добавлении (Приоритет: P2)

Пользователь создаёт группу в Telegram и добавляет бота. Бот определяет, что его добавили в новую группу, автоматически создаёт для неё отдельное рабочее пространство (workspace) и отправляет приветственное сообщение. С этого момента бот обрабатывает все сообщения в этой группе — текст, голос, фото, команды. Каждая группа — это изолированный workspace со своими питомцами, данными и настройками.

Бот поддерживает одновременную работу в неограниченном количестве групп. Один пользователь может состоять в нескольких группах с ботом (например, отдельная группа для каждого питомца или для разных семей). Данные между группами полностью изолированы.

**Почему такой приоритет**: Привязка к группе — это фундамент новой модели авторизации. Без неё бот не может начать работу. Мультитенантность закладывает основу для масштабирования и коммерциализации.

**Независимый тест**: Создать группу, добавить бота. Убедиться, что бот отправил приветственное сообщение. Отправить сообщение в группу — бот обрабатывает его. Создать вторую группу, добавить бота — бот работает в обеих группах независимо.

**Сценарии приёмки**:

1. **Дано**: бот добавлен в группу впервые, **Когда** его добавляют в новую группу, **Тогда** бот создаёт для неё workspace и отправляет приветственное сообщение с кратким описанием возможностей.
2. **Дано**: бот уже работает в группе A, **Когда** его добавляют в группу B, **Тогда** бот создаёт отдельный workspace для группы B и работает в обеих группах независимо.
3. **Дано**: в группе A записан питомец «Луна», в группе B записан питомец «Рекс», **Когда** пользователь отправляет сообщение в группу A, **Тогда** бот видит только данные Луны и не имеет доступа к данным Рекса из группы B.
4. **Дано**: бот привязан к группе, **Когда** бота удаляют из группы, **Тогда** бот прекращает обработку сообщений этой группы, но данные workspace сохраняются (при повторном добавлении бота данные восстанавливаются).

---

### Пользовательская история 3 — Команда /invite выдаёт ссылку на группу (Приоритет: P3)

Член семьи хочет пригласить кого-то. Он отправляет `/invite` в группе с ботом. Бот генерирует или получает пригласительную ссылку на группу и отправляет её в чат. Новый пользователь переходит по ссылке, вступает в группу и автоматически получает доступ ко всем данным семьи — без отдельных инвайт-кодов, без одноразовых токенов.

**Почему такой приоритет**: Замена существующего механизма инвайтов на более простой. Вступление в группу = получение доступа к семье.

**Независимый тест**: Отправить `/invite` в группе. Получить пригласительную ссылку. Перейти по ссылке с другого аккаунта — вступить в группу и получить доступ к данным.

**Сценарии приёмки**:

1. **Дано**: бот привязан к группе, **Когда** пользователь отправляет `/invite` в группе, **Тогда** бот отвечает пригласительной ссылкой на эту группу.
2. **Дано**: бот привязан к группе, **Когда** пользователь отправляет `/invite` в личном чате, **Тогда** бот перенаправляет в группу (стандартное поведение для личного чата).
3. **Дано**: новый пользователь вступил в группу по ссылке, **Когда** он отправляет первое сообщение, **Тогда** бот автоматически регистрирует его как члена семьи и обрабатывает сообщение.
4. **Дано**: пользователь покинул группу, **Когда** он пытается взаимодействовать с ботом, **Тогда** бот не обрабатывает его сообщения (доступ определяется членством в группе).

---

### Пользовательская история 4 — Автоматическая регистрация новых участников группы (Приоритет: P4)

Когда новый пользователь присоединяется к группе (по ссылке, по добавлению администратором или иным способом), бот автоматически регистрирует его как члена семьи. Отдельная процедура авторизации через инвайт-коды не требуется — членство в группе является единственным критерием доступа.

**Почему такой приоритет**: Упрощает онбординг до одного действия — вступить в группу. Устраняет барьер в виде инвайт-кодов.

**Независимый тест**: Добавить нового пользователя в группу. Он отправляет сообщение — бот обрабатывает его и регистрирует как члена семьи.

**Сценарии приёмки**:

1. **Дано**: группа с ботом существует, **Когда** новый пользователь добавлен в группу администратором, **Тогда** бот регистрирует его как члена семьи.
2. **Дано**: группа с ботом существует, **Когда** новый пользователь вступает по пригласительной ссылке, **Тогда** бот регистрирует его как члена семьи.
3. **Дано**: пользователь зарегистрирован как член семьи, **Когда** он покидает группу, **Тогда** его доступ к боту прекращается (но данные, которые он внёс, сохраняются).

---

### Граничные случаи

- Что происходит, если бота добавляют в супергруппу (supergroup) вместо обычной группы? Бот работает одинаково в обоих типах групп — Telegram автоматически конвертирует группы в супергруппы при определённых условиях.
- Что происходит, если бот потерял доступ к группе (был кикнут, группа удалена)? Бот прекращает обработку сообщений, но данные workspace сохраняются. При повторном добавлении бота в ту же группу работа продолжается с существующими данными.
- Что если Telegram не позволяет боту генерировать пригласительную ссылку (нет прав администратора)? Бот сообщает, что ему нужны права администратора для создания ссылки, и предлагает сделать это вручную.
- Что происходит с данными, если пользователь выходит из группы и возвращается? Данные сохраняются — при повторном вступлении пользователь снова получает доступ как член семьи.
- Что если в группу добавлен спам-бот или посторонний человек? Доступ определяется членством в группе — администратор группы контролирует, кто может вступить. Бот не реализует дополнительный контроль доступа поверх механизма группы.
- Что если группа имеет больше участников, чем ожидается для семьи? Бот не ограничивает количество членов workspace'а — это ответственность администратора группы.
- Что если один пользователь состоит в нескольких группах с ботом и пишет в личный чат? Бот показывает список всех групп пользователя и просит перейти в нужную.
- Что если бота повторно добавляют в группу, из которой ранее удалили? Бот восстанавливает связь с существующим workspace'ом и продолжает работу с сохранёнными данными.

## Требования *(обязательно)*

### Функциональные требования

- **FR-001**: Бот НЕ ДОЛЖЕН обрабатывать сообщения по существу в личном чате (private chat). На любое сообщение в личном чате бот ДОЛЖЕН отвечать краткой инструкцией по созданию группы и добавлению бота.
- **FR-002**: При добавлении в группу бот ДОЛЖЕН автоматически создавать для неё изолированный workspace, связывая `chat_id` группы с новым рабочим пространством.
- **FR-003**: Бот ДОЛЖЕН поддерживать одновременную работу в неограниченном количестве групп. Каждая группа — отдельный workspace с полной изоляцией данных (питомцы, записи, напоминания, настройки).
- **FR-004**: Бот ДОЛЖЕН отправлять приветственное сообщение при добавлении в группу с кратким описанием своих возможностей.
- **FR-005**: Команда `/invite` ДОЛЖНА возвращать пригласительную ссылку на текущую группу. Для создания ссылки бот ДОЛЖЕН иметь права администратора в группе.
- **FR-006**: Если у бота нет прав администратора для создания пригласительной ссылки, бот ДОЛЖЕН сообщить об этом и попросить администратора группы предоставить права или создать ссылку вручную.
- **FR-007**: При вступлении нового пользователя в группу бот ДОЛЖЕН автоматически зарегистрировать его как члена семьи без дополнительной процедуры авторизации.
- **FR-008**: При выходе пользователя из группы его доступ к боту ДОЛЖЕН прекратиться. Данные, внесённые этим пользователем, ДОЛЖНЫ сохраняться.
- **FR-009**: При удалении бота из группы бот ДОЛЖЕН прекратить обработку сообщений этой группы. Данные workspace ДОЛЖНЫ сохраняться и восстанавливаться при повторном добавлении бота.
- **FR-010**: Инструкция по созданию группы в личном чате ДОЛЖНА быть лаконичной (3–5 шагов), понятной нетехническому пользователю.
- **FR-011**: Бот ДОЛЖЕН корректно работать как в обычных группах, так и в супергруппах (supergroup).
- **FR-012**: Механизм инвайт-кодов и одноразовых токенов из предыдущей модели авторизации ДОЛЖЕН быть заменён групповой моделью. Команда `/invite` меняет своё поведение с генерации инвайт-кода на выдачу ссылки на группу.

### Ключевые сущности

- **Workspace (рабочее пространство)**: Изолированная единица данных, привязанная к одной Telegram-группе. Содержит своих питомцев, записи, напоминания и настройки. Один бот обслуживает неограниченное количество workspace'ов. Заменяет понятие «Семья» из предыдущей модели.
- **Привязка группы**: Связь между `chat_id` Telegram-группы и workspace'ом. Содержит идентификатор группы, дату привязки и статус (активна/неактивна). Одна группа = один workspace.
- **Член workspace'а** *(изменение существующей)*: Регистрация происходит автоматически при вступлении в группу. Один пользователь может быть членом нескольких workspace'ов (групп). Членство определяется нахождением в группе, а не наличием инвайт-кода.

## Критерии успеха *(обязательно)*

### Измеримые результаты

- **SC-001**: 100% сообщений в личном чате получают ответ с инструкцией — ни одно не обрабатывается по существу.
- **SC-002**: Новый пользователь может начать пользоваться ботом менее чем за 2 минуты: создать группу, добавить бота, отправить первое сообщение и получить ответ.
- **SC-003**: Новый член семьи получает полный доступ к данным питомцев в течение 5 секунд после вступления в группу.
- **SC-004**: Команда `/invite` возвращает рабочую пригласительную ссылку менее чем за 3 секунды.
- **SC-005**: При удалении бота из группы обработка сообщений прекращается мгновенно, а при повторном добавлении данные восстанавливаются в течение 5 секунд.
- **SC-006**: Бот одновременно обслуживает несколько групп без деградации: сообщение в одной группе не блокирует обработку в другой.

### Допущения

- Бот работает в мультитенантной модели: один deploy обслуживает неограниченное количество групп (workspace'ов). Это закладывает основу для коммерциализации.
- Каждая группа — полностью изолированный workspace. Данные между группами не пересекаются, даже если в них состоит один и тот же пользователь.
- Один пользователь может состоять в нескольких группах с ботом (например, отдельная группа для каждого питомца или для разных семей).
- Администратор группы управляет доступом к данным через стандартные механизмы Telegram (добавление/удаление участников). Бот не реализует дополнительный уровень контроля доступа.
- Для создания пригласительной ссылки бот должен иметь права администратора в группе. Если это невозможно, пользователь создаёт ссылку вручную.
- Эта фича заменяет механизм инвайт-кодов и расшаривания сессий из спецификации 001-pet-care-assistant (FR-016a). Сущности `FamilyInvite` и связанная логика одноразовых кодов упраздняются. Понятие «Семья» заменяется на «Workspace».
- Миграция существующих данных (если есть) на новую модель не входит в scope этой фичи.
