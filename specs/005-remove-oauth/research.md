# Исследование: Удаление функционала OAuth

**Дата**: 2026-03-14
**Статус**: Завершено

## Решение 1: Зависимость `cryptography`

**Решение**: Удалить из `requirements.txt`

**Обоснование**: Библиотека `cryptography` импортируется только в `openai_auth_service.py` (строка 27: `from cryptography.fernet import Fernet`) для шифрования/дешифрования OAuth-токенов. Никакой другой код в проекте не использует эту библиотеку напрямую.

**Нюанс**: `python-jose[cryptography]` тянет `cryptography` как транзитивную зависимость для криптографического бэкенда JWT. Это допустимо — транзитивная зависимость управляется `python-jose`, а не нашим кодом.

**Альтернативы**: Оставить как прямую зависимость — отклонено, так как создаёт ложное впечатление об использовании в проекте.

## Решение 2: Зависимость `httpx`

**Решение**: Удалить из `requirements.txt`

**Обоснование**: `httpx` импортируется только в `openai_auth_service.py` (строка 24: `import httpx`) для HTTP-запросов к OpenAI token endpoint (`_request_tokens()`, `_refresh_oauth_tokens()`). Никакой другой код не использует `httpx`.

**Альтернативы**: Оставить на случай будущего использования — отклонено, не добавляем зависимости «про запас».

## Решение 3: Зависимость `python-jose`

**Решение**: Оставить в `requirements.txt`

**Обоснование**: `python-jose` используется в `deps.py` (строка 15: `from jose import jwt`) для JWT Bearer-аутентификации API. Это единственный механизм авторизации для веб-дашборда. Удаление сломает API-доступ.

## Решение 4: Файл `auth.py` — удалить целиком или только OAuth-эндпоинт

**Решение**: Удалить файл целиком

**Обоснование**: В `auth.py` единственный эндпоинт — `GET /api/auth/openai/callback` (OAuth callback). Других маршрутов нет. Роутер `auth_router` регистрируется в `main.py` (строка 151) и импортируется (строка 16) — оба этих места нужно очистить.

## Решение 5: Модель `OAuthCredential` — как удалить безопасно

**Решение**: Удалить класс из `family.py`, создать Alembic-миграцию для DROP TABLE

**Обоснование**: `OAuthCredential` определён в `family.py` (строки 28-77). В этом же файле — модель `ConversationState` (строки 83-140), которую нужно сохранить. Модель `OAuthCredential` не имеет FK-ссылок от других моделей — удаление безопасно. Также нужно убрать импорт из `__init__.py` модуля models.

## Решение 6: Рефакторинг `get_openai_client()`

**Решение**: Заменить на прямое создание клиента через API-ключ

**Обоснование**: Текущая функция в `openai_auth_service.py` (строки 407-440) сначала ищет OAuth-токены в БД, затем fallback на API-ключ. После удаления OAuth вся эта логика не нужна. Вызывающий код в `brain.py` (строка 53) должен создавать `AsyncOpenAI(api_key=settings.OPENAI_API_KEY)` напрямую.

**Альтернативы**: Оставить функцию-обёртку `get_openai_client()` в отдельном файле — отклонено, так как это добавляет ненужный слой абстракции для однострочной операции.

## Решение 7: Telegram-команда `/connectai`

**Решение**: Удалить обработчик и регистрацию

**Обоснование**: Обработчик `handle_connectai()` в `commands.py` (строки 31-64) — единственный OAuth-зависимый хендлер. Регистрация на строке 170. Другие команды (`/help` на строке 169, `/invite` на строке 171) регистрируются отдельными вызовами `router.message.register()` и не затрагиваются.

## Решение 8: Тесты

**Решение**: Удалить `test_openai_auth.py`, очистить `conftest.py` и `test_config.py`

**Обоснование**:
- `test_openai_auth.py` — тесты исключительно OAuth-функциональности, удаляется целиком
- `conftest.py` — переменные `OPENAI_OAUTH_CLIENT_ID` и `OAUTH_ENCRYPTION_KEY` в списке `_OPTIONAL_ENV_VARIABLES` (строки 32-33) — удалить
- `test_config.py` — тесты для OAuth-полей конфигурации — удалить OAuth-специфичные тест-методы

## Решение 9: Env-файлы

**Решение**: Удалить OAuth-переменные из `.env.example`

**Обоснование**: Строки 12-13 в `.env.example` содержат `OPENAI_OAUTH_CLIENT_ID=` и `OAUTH_ENCRYPTION_KEY=`. В `.env.dev.example` и `.env.prod.example` OAuth-переменных нет.
