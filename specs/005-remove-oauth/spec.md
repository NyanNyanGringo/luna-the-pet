# Feature Specification: Удаление функционала OAuth

**Feature Branch**: `005-remove-oauth`
**Created**: 2026-03-14
**Status**: Draft
**Input**: User description: "Удаляем функционал (логин через) OAuth. Оставляем ТОЛЬКО API доступ. Важно, чтобы при очистке функционала OAuth НЕ осталось хвостов, а также мы НЕ сломали API доступ."

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Бот продолжает работать через API-ключ после удаления OAuth (Priority: P1)

Администратор бота настраивает систему, указывая API-ключ OpenAI в переменных окружения. Бот использует этот ключ для всех запросов к OpenAI. Никаких OAuth-потоков, команд авторизации или хранения токенов в системе больше нет — всё работает исключительно через API-ключ.

**Why this priority**: Главная цель — убедиться, что основная функциональность бота (общение с OpenAI) не сломана после удаления OAuth. Без этого бот бесполезен.

**Independent Test**: Запустить бота с указанным `OPENAI_API_KEY`, отправить сообщение в Telegram-группу — бот должен ответить, используя OpenAI API.

**Acceptance Scenarios**:

1. **Given** бот запущен с настроенным API-ключом, **When** пользователь отправляет сообщение боту, **Then** бот обрабатывает запрос через OpenAI и возвращает ответ
2. **Given** бот запущен без API-ключа, **When** система стартует, **Then** выдаётся ошибка конфигурации о необходимости указать API-ключ
3. **Given** бот запущен с API-ключом, **When** пользователь пытается вызвать команду `/connectai`, **Then** бот сообщает, что эта команда больше не доступна, или не реагирует

---

### User Story 2 — Полная очистка кодовой базы от OAuth-артефактов (Priority: P1)

Разработчик проверяет проект после удаления OAuth. В коде не осталось: OAuth-эндпоинтов, сервисов авторизации через OAuth, Telegram-команд для OAuth, конфигурационных переменных OAuth, тестов OAuth. Кодовая база чиста и не содержит мёртвого кода.

**Why this priority**: Равноценно P1, так как «хвосты» OAuth в коде — это потенциальные баги, путаница для разработчиков и нарушение безопасности (неиспользуемые зашифрованные токены в БД).

**Independent Test**: Выполнить поиск по ключевым словам OAuth (oauth, connectai, PKCE, code_verifier, authorization_code, OPENAI_OAUTH_CLIENT_ID, OAUTH_ENCRYPTION_KEY) — ни одного совпадения в рабочем коде не должно быть найдено.

**Acceptance Scenarios**:

1. **Given** OAuth удалён, **When** разработчик ищет OAuth-артефакты в коде, **Then** ни одного упоминания OAuth-логики не найдено (допустимы упоминания в миграциях, коммитах и этой спецификации)
2. **Given** OAuth удалён, **When** разработчик просматривает зависимости проекта, **Then** зависимости, используемые только для OAuth (cryptography, httpx), удалены или помечены как необязательные, если используются для других целей
3. **Given** OAuth удалён, **When** разработчик проверяет конфигурационные файлы (.env.example и др.), **Then** переменные `OPENAI_OAUTH_CLIENT_ID` и `OAUTH_ENCRYPTION_KEY` отсутствуют

---

### User Story 3 — Сохранение JWT-авторизации для веб-API (Priority: P1)

Веб-дашборд или внешний клиент отправляет запрос к API с JWT Bearer-токеном и заголовком `X-Workspace-Id`. Система валидирует токен, определяет пользователя и предоставляет доступ к данным workspace — точно так же, как и до удаления OAuth.

**Why this priority**: JWT-аутентификация — единственный оставшийся механизм авторизации для API. Любое его повреждение полностью сломает доступ к данным через веб-интерфейс.

**Independent Test**: Отправить запрос к защищённому API-эндпоинту с валидным JWT-токеном — запрос должен быть обработан успешно. Отправить запрос без токена — должна вернуться ошибка авторизации.

**Acceptance Scenarios**:

1. **Given** JWT-авторизация настроена, **When** клиент отправляет запрос с валидным Bearer-токеном и X-Workspace-Id, **Then** система возвращает данные
2. **Given** JWT-авторизация настроена, **When** клиент отправляет запрос без токена, **Then** система возвращает ошибку 401
3. **Given** JWT-авторизация настроена, **When** клиент отправляет запрос с невалидным токеном, **Then** система возвращает ошибку 401

---

### User Story 4 — Миграция базы данных для удаления OAuth-таблицы (Priority: P2)

Администратор выполняет миграцию БД. Таблица `oauth_credential` удаляется. Остальные таблицы и их данные не затронуты. Миграция обратима (есть downgrade).

**Why this priority**: Важная часть очистки, но может быть выполнена отдельным шагом после удаления кода. Данные в таблице `oauth_credential` больше не используются.

**Independent Test**: Выполнить `alembic upgrade head` — миграция проходит без ошибок, таблица `oauth_credential` удалена, остальные таблицы на месте.

**Acceptance Scenarios**:

1. **Given** база данных содержит таблицу `oauth_credential`, **When** выполняется миграция upgrade, **Then** таблица `oauth_credential` удалена, остальные таблицы не изменены
2. **Given** таблица `oauth_credential` удалена, **When** выполняется миграция downgrade, **Then** таблица `oauth_credential` воссоздаётся (пустой)

---

### Edge Cases

- Что происходит, если в БД остались записи в `oauth_credential` на момент миграции? — Данные удаляются вместе с таблицей. Это допустимо, так как токены больше не используются.
- Что если зависимость `cryptography` используется где-то ещё, помимо OAuth? — Перед удалением проверить все импорты; если используется только для OAuth — удалить, иначе оставить.
- Что если зависимость `httpx` используется где-то ещё? — Аналогично: проверить перед удалением.
- Что если пользователь вызовет старую команду `/connectai`? — Команда должна быть удалена из обработчиков. Если пользователь введёт её, бот просто не отреагирует.
- Что если `python-jose` используется для JWT (не только для OAuth)? — `python-jose` используется для JWT-авторизации API и должен остаться.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА удалить OAuth-эндпоинт `GET /api/auth/openai/callback` и весь связанный с ним обработчик
- **FR-002**: Система ДОЛЖНА удалить сервис `openai_auth_service` целиком (PKCE, обмен токенов, шифрование, рефреш)
- **FR-003**: Система ДОЛЖНА удалить Telegram-команду `/connectai` и её обработчик
- **FR-004**: Система ДОЛЖНА удалить модель `OAuthCredential` из кода приложения
- **FR-005**: Система ДОЛЖНА создать миграцию для удаления таблицы `oauth_credential` из БД
- **FR-006**: Система ДОЛЖНА удалить конфигурационные параметры `OPENAI_OAUTH_CLIENT_ID` и `OAUTH_ENCRYPTION_KEY` из настроек и примеров env-файлов
- **FR-007**: Система ДОЛЖНА удалить тесты OAuth (`test_openai_auth.py`)
- **FR-008**: Система ДОЛЖНА удалить зависимости, используемые только для OAuth (после проверки, что они не используются в другом месте)
- **FR-009**: Система ДОЛЖНА сохранить JWT Bearer-аутентификацию в `deps.py` полностью работоспособной
- **FR-010**: Система ДОЛЖНА сохранить настройку `OPENAI_API_KEY` как единственный способ подключения к OpenAI
- **FR-011**: Система ДОЛЖНА удалить любую логику fallback/переключения между OAuth и API-ключом — должен остаться только путь через API-ключ
- **FR-012**: Система ДОЛЖНА убрать все упоминания OAuth из inline-комментариев, docstrings и конфигурационных файлов в рабочем коде

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Бот отвечает на сообщения в Telegram-группе через API-ключ OpenAI — 100% функциональность сохранена
- **SC-002**: Все защищённые API-эндпоинты корректно обрабатывают JWT Bearer-токены — 0 регрессий в авторизации
- **SC-003**: Поиск по ключевым словам OAuth в рабочем коде (исключая миграции, git-историю и спецификации) возвращает 0 результатов
- **SC-004**: Все существующие тесты (кроме удалённых OAuth-тестов) проходят успешно — 0 падений
- **SC-005**: Миграция БД выполняется без ошибок в обоих направлениях (upgrade и downgrade)

## Assumptions

- Зависимость `python-jose` используется для JWT-авторизации API и должна быть сохранена
- Зависимость `cryptography` используется только для Fernet-шифрования OAuth-токенов — подлежит удалению (требует верификации при реализации)
- Зависимость `httpx` используется только для обмена OAuth-токенов — подлежит удалению (требует верификации при реализации)
- Существующие данные в таблице `oauth_credential` не представляют ценности и могут быть удалены
- Никакие внешние системы не зависят от OAuth-эндпоинта `/api/auth/openai/callback`
